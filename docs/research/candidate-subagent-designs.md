# Candidate subagent designs and external evidence

_Research snapshot: 2026-08-26. Question: [issue #2](https://github.com/Blaise-g/pi-subagents-minimal/issues/2); v1 boundary: [map #1](https://github.com/Blaise-g/pi-subagents-minimal/issues/1)._

## Conclusion

None of the three packages is a v1 template. **Arhen has the closest execution kernel** (one call for one task or a bounded flat batch, in-process fresh `AgentSession`s, strict read-only default, ordered concurrency, and bounded returned text), but its graph, chain, background, intercom, mailbox, write/worktree, fuzzy agent-file routing, and six-tool lifecycle are outside v1. **Tintinweb has the strongest reusable child-session and lifecycle mechanics**, but parallelism is multiple `Agent` tool calls rather than one Flat-batch request, and most of its agent catalog, persistence, resumption, scheduling, nesting, worktrees, UI, memory, steering, RPC, and extension inheritance are unnecessary. **Nico is the least suitable runtime base**: it launches separate Pi processes and has become a broad orchestration platform, although its output/artifact bounds and extensive failure handling are useful design evidence.

The public evidence establishes that all three are real, actively published implementations and that Nico/Tintinweb receive detailed user reports. It does **not** establish comparative workflow quality, safety, or Added context cost. Downloads and stars are adoption signals, not proof; [ticket #3](https://github.com/Blaise-g/pi-subagents-minimal/issues/3) must measure context under the agreed protocol.

## Comparison against v1

### Nico Bailon

**What it implements.** One `subagent` schema includes single execution plus scripted workflows, context selection, background control, resumption/steering, worktrees, budgets, acceptance, missions, schedules, artifacts, structured output, model overrides, and management actions ([schema lines 257–422](https://github.com/nicobailon/pi-subagents/blob/6cb9fb3c82a767683e79889d75fcb8ff1d1537bc/src/extension/schemas.ts#L257-L422)). The package ships six built-in roles, including implementation and review roles that v1 explicitly must not duplicate ([README built-ins](https://github.com/nicobailon/pi-subagents/blob/6cb9fb3c82a767683e79889d75fcb8ff1d1537bc/README.md#L47-L61)). Despite “child session” language, the implementation resolves a Pi command and calls Node `spawn`, communicating over stdout/stderr ([`execution.ts` lines 542–577](https://github.com/nicobailon/pi-subagents/blob/6cb9fb3c82a767683e79889d75fcb8ff1d1537bc/src/runs/foreground/execution.ts#L542-L577)); abort escalates process termination ([lines 1399–1410](https://github.com/nicobailon/pi-subagents/blob/6cb9fb3c82a767683e79889d75fcb8ff1d1537bc/src/runs/foreground/execution.ts#L1399-L1410)). This mirrors Pi's official subprocess example, which explicitly describes one separate Pi process per child and caps a batch at eight/four concurrent ([official source lines 1–33](https://github.com/badlogic/pi-mono/blob/8fa7eebd235355522c8104166b4f1f959b4e2f10/packages/coding-agent/examples/extensions/subagent/index.ts#L1-L33)); it does not satisfy the likely minimal in-process seam under investigation in [#4](https://github.com/Blaise-g/pi-subagents-minimal/issues/4).

**Reusable.** Keep the principle, not the subsystem: cap model-visible output and preserve a recovery path. Nico defaults to 200 KiB/5,000 lines and applies truncation after artifact persistence ([default lines 2299–2302](https://github.com/nicobailon/pi-subagents/blob/6cb9fb3c82a767683e79889d75fcb8ff1d1537bc/src/shared/types.ts#L2299-L2302); [application lines 2090–2105](https://github.com/nicobailon/pi-subagents/blob/6cb9fb3c82a767683e79889d75fcb8ff1d1537bc/src/runs/foreground/execution.ts#L2090-L2105)). Also reuse its insistence on explicit status and partial-result recovery, but only for v1 terminal states.

**Do not copy.** Subprocess/RPC infrastructure, workflow JavaScript, chains, dynamic fan-out, missions, schedules, watchdog, acceptance engine, intercom, nested delegation, external CLIs, worktrees, Fleet UI, role memory, agent authoring, or packaged roles. They are outside [map #1](https://github.com/Blaise-g/pi-subagents-minimal/issues/1) and dominate the measured source/package shape.

### Tintinweb

**What it implements.** Each run creates an in-process Pi session. A `DefaultResourceLoader` controls context files, skills, themes, and extension loading; a fresh/in-memory or persisted `SessionManager` is selected; then `createAgentSession` receives the effective tool allow/deny set ([`agent-runner.ts` lines 640–717](https://github.com/tintinweb/pi-subagents/blob/ad81024825b315577692b785831262874e66be95/src/agent-runner.ts#L640-L717), [lines 886–940](https://github.com/tintinweb/pi-subagents/blob/ad81024825b315577692b785831262874e66be95/src/agent-runner.ts#L886-L940)). Fresh context is the default; parent context is prepended only when explicitly requested ([lines 1029–1045](https://github.com/tintinweb/pi-subagents/blob/ad81024825b315577692b785831262874e66be95/src/agent-runner.ts#L1029-L1045)). Flat parallelism is emergent: the Orchestrator emits several `Agent` calls in one turn and Pi dispatches them concurrently, rather than sending one batch value ([tool guidance lines 1398–1417](https://github.com/tintinweb/pi-subagents/blob/ad81024825b315577692b785831262874e66be95/src/index.ts#L1398-L1417)). A manager queues background runs, wires already-aborted and future parent signals, and releases the exact acquired pool on settlement ([`agent-manager.ts` lines 398–534](https://github.com/tintinweb/pi-subagents/blob/ad81024825b315577692b785831262874e66be95/src/agent-manager.ts#L398-L534), [lines 580–817](https://github.com/tintinweb/pi-subagents/blob/ad81024825b315577692b785831262874e66be95/src/agent-manager.ts#L580-L817)).

**Reusable.** The strongest patterns are: construct children from `DefaultResourceLoader` + `SessionManager` + `createAgentSession`; default to fresh history; exclude delegation tools from children; validate tool names; propagate cancellation both before and after queueing; and centralize acquire/release so cancellation cannot double-free or leak capacity. For v1, simplify further to `noExtensions: true`, no persistence, one pool, and one batch-owned abort tree.

**Do not copy.** Multiple parent tools (`Agent`, result, steer), default agents, mentions, memory, extension/skill inheritance, persistence/resume, nested delegation, worktrees, schedules, RPC/event bus, model fuzzing, Fleet/conversation UI, and two concurrency pools. These solve a broader Claude-Code-compatible product, not the narrow boundary.

### Arhen

**What it implements.** Its single `subagent` call directly models one task, `tasks`, or `chain`; each task can add graph dependencies, write access, arbitrary tools, timeout, model, and thinking, while top-level fields add concurrency, background waiting, notifications, and intercom ([`schemas.ts` lines 8–75](https://github.com/arhen/pi-extensions/blob/de266e7cda20c312f19e26cca2a3b1c20b8234e5/packages/core/pi-core-subagent/src/schemas.ts#L8-L75)). Children use `DefaultResourceLoader({noExtensions:true})`, a fresh `SessionManager.create`, explicit tools, and in-process `createAgentSession` ([`manager.ts` lines 985–1025](https://github.com/arhen/pi-extensions/blob/de266e7cda20c312f19e26cca2a3b1c20b8234e5/packages/core/pi-core-subagent/src/manager.ts#L985-L1025)). Its default read-only list is exactly `read, grep, find, ls`; batches cap at 16 tasks, default concurrency 3, maximum 8 ([`manager.ts` lines 58–79](https://github.com/arhen/pi-extensions/blob/de266e7cda20c312f19e26cca2a3b1c20b8234e5/packages/core/pi-core-subagent/src/manager.ts#L58-L79), [lines 1270–1342](https://github.com/arhen/pi-extensions/blob/de266e7cda20c312f19e26cca2a3b1c20b8234e5/packages/core/pi-core-subagent/src/manager.ts#L1270-L1342)). Returned child and aggregate text is UTF-8 bounded at 24 KiB, with full output recoverable through the child session file ([`format.ts` lines 17–26](https://github.com/arhen/pi-extensions/blob/de266e7cda20c312f19e26cca2a3b1c20b8234e5/packages/core/pi-core-subagent/src/format.ts#L17-L26), [lines 223–251](https://github.com/arhen/pi-extensions/blob/de266e7cda20c312f19e26cca2a3b1c20b8234e5/packages/core/pi-core-subagent/src/format.ts#L223-L251)).

**Reusable.** This is the best shape to reduce: one top-level tool; mutually exclusive single/Flat-batch modes; a small task record; strict read-only capability allowlist; bounded task count and concurrency; ordered results; no child extensions; fresh sessions; final-answer-only return with a byte cap. Prefer an actual discriminated union (`mode: "single" | "batch"`) over Arhen's all-optional overlapping shape.

**Do not copy.** Graph `needs`, chain, write/worktree, background status/result/await tools, notifications, intercom/mailbox, steering, fuzzy description-based agent-file substitution, and inline role invention. In particular, agent-file matching can silently replace requested tools ([`manager.ts` lines 838–856](https://github.com/arhen/pi-extensions/blob/de266e7cda20c312f19e26cca2a3b1c20b8234e5/packages/core/pi-core-subagent/src/manager.ts#L838-L856)); that is the wrong authority model for durable v1 Agent definitions.

## Independent experience and safety cautions

These are **user-authored reports**, not maintainer capability claims. They show exercised paths and failure classes; self-selected issue traffic cannot estimate incidence or compare quality.

- **Prompt/schema size is a real cost surface.** A Tintinweb user reported an Agent description over 3,000 tokens; the maintainer added compact/custom modes rather than claiming it was free ([#91](https://github.com/tintinweb/pi-subagents/issues/91)). Nico independently received a measured cold-load report of 91.6 ms median/3,363 ms peak on v0.53.0, attributed to 51 static imports ([#1330](https://github.com/nicobailon/pi-subagents/issues/1330)); Tintinweb has a current report of 647–1,098 ms source-entry loading versus 86–143 ms compiled ([#252](https://github.com/tintinweb/pi-subagents/issues/252)). These timings are reporter environments, not controlled cross-candidate benchmarks, but support keeping one small schema and no catalog/prompt injection.
- **Cancellation and waiting need explicit semantics.** Tintinweb users found that cancelling a result wait did not cancel the wait ([fixed #158](https://github.com/tintinweb/pi-subagents/issues/158)) and that an unbounded wait can occupy a parent for hours ([open #229](https://github.com/tintinweb/pi-subagents/issues/229)). Arhen users report its hard-coded 180-second no-event watchdog kills healthy silent commands ([open #2](https://github.com/arhen/pi-extensions/issues/2)). V1 should distinguish “abort Delegation,” “stop waiting,” timeout, and child failure; silence alone is not proof of a stall.
- **Failure must not look successful.** Tintinweb still has a report that startup exceptions become successful tool results ([open #179](https://github.com/tintinweb/pi-subagents/issues/179)). Nico users found workflow result-shape ambiguity could waste already-completed fan-out ([#1351](https://github.com/nicobailon/pi-subagents/issues/1351)) and reported a child tool-result hang across two releases ([#1331](https://github.com/nicobailon/pi-subagents/issues/1331)). V1 needs one small, unambiguous result union and tests at the Pi `ToolResultMessage.isError` boundary.
- **Isolation is not just a separate session.** A Tintinweb user reproduced worktree agents writing into the parent checkout because inherited path context named the wrong cwd ([fixed #250](https://github.com/tintinweb/pi-subagents/issues/250)). Nico users showed timeout reports can omit mutations already made in a shared cwd ([#1409](https://github.com/nicobailon/pi-subagents/issues/1409)). V1 excludes writers, but repository research can still execute `bash` if exposed; therefore “report-only” must be an enforced tool allowlist, not merely a role prompt. Prefer no `bash` for read-only roles unless a workflow battery proves it necessary.
- **Child lifecycle cleanup is mandatory in-process.** A Tintinweb user traced missing child `session_shutdown` to accumulating timers/watchers and a later process crash; it was fixed before 0.18.2 ([#242](https://github.com/tintinweb/pi-subagents/issues/242)). V1 must pair every bound lifecycle with shutdown—or avoid child extensions entirely and still dispose every session in `finally`.
- **Schema overlap causes model retries.** Arhen's all-optional single/tasks/chain schema allows conflicting modes; a user observed four repeated invalid calls ([open #1](https://github.com/arhen/pi-extensions/issues/1)). A discriminant is safer and cheaper than prose explaining exclusions.

Historical npm downloads—[Nico 321,446](https://api.npmjs.org/downloads/point/2026-07-26:2026-08-24/pi-subagents), [Tintinweb 43,844](https://api.npmjs.org/downloads/point/2026-07-26:2026-08-24/%40tintinweb%2Fpi-subagents), [Arhen 12,614](https://api.npmjs.org/downloads/point/2026-07-26:2026-08-24/%40arhen%2Fpi-core-subagent)—show distribution, including CI/cache/repeat downloads. They do not show successful use, unique users, workflow outcomes, or safety.

## Recommended v1 mechanisms

1. **One discriminated tool:** `{mode:"single", task}` or `{mode:"batch", tasks}`; no management actions. Validate the entire request, count limit, role existence, and capability set before launching any child.
2. **In-process, fresh children:** `DefaultResourceLoader` with child extensions/prompt templates/themes disabled, an in-memory/fresh `SessionManager`, explicit read-only tools, and `createAgentSession`. Never inherit parent conversation; the Orchestrator must supply a bounded, self-contained task.
3. **Flat bounded concurrency:** a small worker pool that preserves input order; one `AbortController` per Delegation linked to every queued/running child; deterministic cleanup with `Promise.allSettled` and `session.dispose()` in `finally`.
4. **Small terminal contract:** success/failure/cancelled per child plus final text, capped by UTF-8 bytes. Batch result preserves order and partial successes. Any truncation names a recoverable report/session path only if v1 deliberately persists one.
5. **Capabilities from durable definitions:** research/exploration may select a definition; existing review/simplification skills remain the authority for their roles. Children receive no delegation tool, preventing nesting by construction.
6. **Verification derived from observed failures:** test conflicting modes, unknown roles/tools, partial batch failure, cancellation while queued/running/waiting, provider/startup failure marked as error, output truncation, no parent-history inheritance, no child delegation tool, and disposal after every terminal path.

## Evidence gaps and decision impact

- No candidate publishes controlled results on this project's four workflows against a frozen oracle. [#9](https://github.com/Blaise-g/pi-subagents-minimal/issues/9) remains necessary.
- No evidence here measures serialized schema, added prompt text, or observed input-token delta against a no-package baseline. [#3](https://github.com/Blaise-g/pi-subagents-minimal/issues/3) and then [#8](https://github.com/Blaise-g/pi-subagents-minimal/issues/8) remain necessary; source/package LOC cannot substitute for those measurements.
- Public issues provide rich failure reports for Nico/Tintinweb but sparse independent evidence for the newer Arhen package. No candidate offers a comparative security review or reliability rate.
- Child-session API compatibility and exact cleanup requirements must be resolved by [#4](https://github.com/Blaise-g/pi-subagents-minimal/issues/4); this report only identifies candidate implementations of the seam.

**Appears to unblock:** [#5](https://github.com/Blaise-g/pi-subagents-minimal/issues/5) (reject package-owned duplicate review roles; compare skill-backed versus narrowly discovered Agent definitions), [#7](https://github.com/Blaise-g/pi-subagents-minimal/issues/7) (concurrency/cancellation/failure choices now have concrete failure cases), and the candidate-derived scenarios in [#9](https://github.com/Blaise-g/pi-subagents-minimal/issues/9). It informs but does not unblock #8 or #10. **New ticket suggested:** a focused prototype/test ticket for in-process child disposal and tool-boundary error classification if #4 does not already verify both.
